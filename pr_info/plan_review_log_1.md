Reviewing plan steps; verifying a few facts in `adapters/llm.py` and the test conftest.Checking how mcp_coder's timeout handling interacts with `NodeCancelledError` — a possible plan gap.`pr_info/steps/step_5.md:75` — high — The plan runs both timeouts inside the turn's own task (`asyncio.timeout` for the overall cap, `wait_for(anext(...))` for inactivity). mcp_coder's `_is_node_cancelled` docstring says langgraph's retry layer turns an `asyncio.CancelledError` raised in a node body into `NodeCancelledError`, which is a plain `Exception`. When either timeout cancels the stalled model node, the error that comes out can be `NodeCancelledError` instead of `CancelledError`. Then `asyncio.timeout.__aexit__` and `wait_for` no longer convert it to `TimeoutError`, and the `except NodeCancelledError → raise CancelledError` branch reports the timeout as a Stop: no message, and Chainlit swallows it. mcp_coder avoids this because its timeouts run on the consumer side of a thread and queue. Fix: in the `NodeCancelledError` branch, check first whether the overall timer (`cm.expired()`) or an idle timer fired and return the matching timeout message. Doing that needs the idle wait to tell you when it expired, e.g. an `asyncio.timeout` that is rescheduled after each event instead of `wait_for`. Also add a probe that confirms which exception comes out when a node is cancelled from outside.
`pr_info/steps/step_5.md:102` — high — The inactivity and overall timeout tests stall inside `_agenerate`, which runs in the model node's body. These are exactly the cases where the wrapping above happens, so as planned they will fail (Stop instead of a timeout message) or pass only by luck of langgraph version. The step does not say what the expected exception path is. State it, and tie it to the probe and the fix above.
`pr_info/steps/step_5.md:108` — medium — The `NodeCancelledError` test only checks that `run_turn` ends with a `CancelledError`. That also passes if langgraph does not wrap at all, so it does not prove the re-raise branch runs. Have the probe confirm that a `CancelledError` raised in `_agenerate` comes out as `NodeCancelledError` from `astream_events`, or have the test assert `__cause__` is a `NodeCancelledError`.
